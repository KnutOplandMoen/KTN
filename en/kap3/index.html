Overview

The big picture

The transport layer bridges the gap between the unreliable network and the applications that demand order and guarantees.

The transport layer is like the difference between sending a postcard and a registered letter. A postcard is quick and cheap — you write it, drop it in the mailbox, and hope it arrives. You never find out whether the recipient got it. A registered letter costs more effort (receipt, tracking, signature upon delivery), but you know it got there. In the networking world, UDP is the postcard and TCP is the registered letter.

The network layer (IP) delivers packets between machines — but it provides no guarantees. Packets can disappear, arrive out of order, or be duplicated. The transport layer sits on top of IP and offers two vastly different services to applications: UDP merely adds port numbers (so the right process receives the packet) and a simple checksum, but otherwise inherits IP's "best effort" delivery. TCP adds reliable delivery, ordering guarantees, flow control, and congestion control — everything IP lacks.

When is each used?

When you download a file, TCP is used because every single byte must arrive in the correct order. When you talk on Discord, UDP is used because it is more important that the audio arrives quickly than that every single audio packet arrives — a lost packet causes a small glitch, but a delayed packet makes the conversation unusable.

The chapter builds up layer by layer: first multiplexing and UDP (the simple part), then the principles of reliable data transfer (the rdt protocols), then TCP with everything it entails, and finally congestion control — the mechanisms that prevent the Internet from collapsing under its own traffic.

Test yourself

Check whether you have understood the most important concepts from this chapter.

Question

An application sends short messages where low latency is critical, but it is acceptable to lose some messages. Which transport protocol should be used?

UDP is the right choice here. TCP's three-way handshake, retransmission, and flow control add latency that is undesirable in real-time applications. UDP sends data immediately without waiting for confirmation — perfect for use cases like voice, gaming, and DNS lookups where speed trumps reliability.
Question

What is the main difference between Go-Back-N (GBN) and Selective Repeat (SR) when a packet is lost?

In Go-Back-N, the sender must retransmit the lost packet and all subsequent packets in the window, because the receiver discards packets that arrive out of order. In Selective Repeat, the receiver buffers out-of-order packets and the sender only needs to retransmit the single lost packet — more efficient, but requires more complex buffering at the receiver.
