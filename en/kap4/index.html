The Network Layer

How a packet actually finds its way from your machine to a server on the other side of the globe — and everything that happens inside the routers along the way.

Overview

The big picture

The network layer data plane is about one thing: when a packet lands on a router, how does it find the correct output — in nanoseconds?

Think of the Internet as an enormous highway system. Each router is an intersection, and the forwarding table is the road signs. When a packet arrives at a router, it reads the destination IP (like reading a road sign), looks it up in the forwarding table (like checking the directional signs), and sends the packet out the correct port (takes the right exit). IP addresses function like postal codes — the CIDR prefix tells you the region, and the host part is the specific house.

★ A real-world example

When your packet travels from Trondheim to a Netflix server in Amsterdam, it may pass through 12 routers. At each router, the same thing happens: read the destination IP, look it up in the table, forward the packet. The entire process takes nanoseconds. What makes this possible is that the network layer data plane is extremely simple — match an address, choose a port, done. All the complexity (routing algorithms, BGP, OSPF) lives in the control plane, which runs in the background.

In this chapter we look at what happens inside the router: the architecture of input ports, switching fabric and output ports; longest prefix match for selecting the correct route; queues and scheduling when there is congestion; and then the IP protocol itself — the datagram format, CIDR addressing, DHCP, NAT and IPv6.

Test yourself

Quick quiz — chapter 4

Check whether you have grasped the essentials of the network layer data plane.

Question 1

A router has the following forwarding table. Which output port is selected for a packet with destination 10.1.5.200?

PrefixOutput port
10.0.0.0/80
10.1.0.0/161
10.1.4.0/222
0.0.0.0/03
Correct! All three prefixes (/8, /16, /22) match 10.1.5.200, but longest prefix match selects /22 because it is the most specific. The address 10.1.5.200 = 10.1.0000 01.11001000, and the first 22 bits match the prefix 10.1.4.0/22 (10.1.0000 01xx xxxx.xxxx xxxx). The default route is only used when no other prefixes match.
Question 2

A home network with 5 devices uses NAT. All devices are browsing the web simultaneously. What does an external web server see as the source IP on all requests?

Correct! The NAT router rewrites the source IP on all outgoing packets to its single public address. To distinguish between internal devices, it uses different source port numbers, which it stores in the NAT table. When the reply comes back, the router looks up the port number in the table and forwards the packet to the correct internal device.
Question 3

What is the most important improvement in IPv6 compared to IPv4 in terms of forwarding performance in routers?

Correct! In IPv4, the header checksum must be recomputed at every single router because the TTL field changes at each hop. IPv6 removed the checksum entirely (the transport layer has its own), and the header is fixed at 40 bytes with no options. The result is faster forwarding in the data plane.
