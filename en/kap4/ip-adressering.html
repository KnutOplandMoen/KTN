09 · The IP datagram

The format that carries everything

Everything we have seen so far is generic. Now we meet the concrete: what an actual IPv4 packet looks like, and why each field is where it is.

FieldWhat it does
Version4 for IPv4, 6 for IPv6. Two entirely different formats.
HLenHeader length in 32-bit words. Usually 5 (= 20 bytes, no options).

IP fragmentation

A datagram can be up to 65 535 bytes, but each link has an MTU (Maximum Transmission Unit) — the largest frame it can carry. Ethernet typically has MTU = 1500 bytes. If a datagram is larger than the MTU on the next link, the router must fragment it into smaller pieces.

Three fields in the IPv4 header control fragmentation:

  • 16-bit Identifier — all fragments from the same original datagram receive the same value, so the receiver can group them.
  • Flags — the MF bit (More Fragments) is set in all fragments except the last. The DF bit (Don’t Fragment) forbids fragmentation; the router drops the packet instead and sends an ICMP error message.
  • Fragment Offset — indicates where in the original datagram this fragment belongs, measured in units of 8 bytes.

Example: 4000-byte datagram over MTU = 1500

A datagram of 4000 bytes (20 header + 3980 payload) must be split. Each fragment gets its own 20-byte IP header, so the payload per fragment is 1500 − 20 = 1480 bytes:

FragmentPayloadOffsetMFTotal
#11480 bytes011500
#21480 bytes18511500
#31020 bytes37001040

The offset values are 1480/8 = 185 and 2960/8 = 370. Total: 1480 + 1480 + 1020 = 3980 bytes payload, which equals the original.

Reassembly occurs only at the destination

Routers along the way do not reassemble fragments — that is the end system’s job. The reason is simple: fragments may take different routes through the network, so only the destination is guaranteed to see all of them. If one fragment is lost, the receiver discards the rest and TCP/the application handles retransmission.

10 · IP addresses & subnets

Addresses are bound to interfaces

An IP address does not identify a machine — it identifies an interface. A router with eight ports has eight addresses.

An IP address is 32 bits, written as four decimal numbers separated by dots (dotted decimal). But it is bound to an interface, not a machine. Your laptop has two interfaces (Ethernet + WiFi) and gets two different IP addresses.

Subnets: «the same neighborhood»

A subnet is a set of interfaces that can reach each other directly without passing through a router. All machines on the same Ethernet switch or WiFi are on the same subnet.

The recipe for identifying subnets: detach all interfaces from routers and hosts. The connected «islands» that remain are the subnets.

The addresses on a subnet share a common network part (high-order bits) and vary only in the host part (low-order bits). For example: 223.1.1.0/24 has a 24-bit network part and an 8-bit host part (256 addresses).

11 · CIDR

Classless addressing

The old classes (/8, /16, /24) wasted enormous amounts of addresses. CIDR lets the network part be any number between 0 and 32.

CIDR — Classless Inter-Domain Routing — drops the fixed classes and allows the prefix length to be arbitrary. 200.23.16.0/23 means «the first 23 bits are the network part, the last 9 are the host part», giving 2⁹ = 512 addresses.

Route aggregation

CIDR enables hierarchical addressing. An ISP that owns 200.23.16.0/20 can advertise that single route to the rest of the Internet, even though it internally divides the space into eight /23 blocks for eight customer organizations. The rest of the Internet does not need to know about the subdivision — only that «everything starting with 200.23.16.0/20 goes to this ISP.»

When an organization switches ISPs, the new ISP advertises a more specific route (longer prefix), and thanks to LPM traffic finds its way correctly. The system is self-repairing.

Who allocates addresses?

ICANN (Internet Corporation for Assigned Names and Numbers) allocates IP address blocks through five Regional Internet Registries (RIRs). ICANN allocated the last IPv4 block to an RIR in 2011 — the global pool is empty.

12 · DHCP

Getting an address automatically

DHCP — Dynamic Host Configuration Protocol — lets a machine request and receive an IP address when it joins the network.

Manual configuration works for servers, but is impossible for laptops that constantly switch networks. DHCP solves this with a four-step dance — all sent as broadcast, because the client initially does not even know its own address.

0 / 4

DHCP delivers more than just an IP address. The reply typically also includes: the address of the first-hop router (default gateway), the address of the DNS server, and the subnet mask.

ⓘ Implementation detail: UDP ports 67 and 68

DHCP runs over UDP (not TCP — there is no established connection yet). The server always listens on port 67; the client listens on port 68. These port numbers are fixed and inherited from the older BOOTP protocol. Because the client does not yet have an IP address, both the initial Discover and the Request are sent from source address 0.0.0.0:68 to 255.255.255.255:67.

Why is the DHCP request sent as broadcast, even when the client knows the server address?

Correct! The broadcast in step 3 signals to all DHCP servers: «I chose this server; the others can release their reservations.»
13 · NAT

Why the entire household shares one IP

Network Address Translation lets an entire private network share one public IP address. It saved IPv4 — but violates the end-to-end principle.

IPv4 has 2³² ≈ 4.3 billion addresses. That is not enough for all the world’s devices. NAT solves this by having all machines on a private network share one public address externally. Three address ranges are reserved for private use and are never routable on the public Internet:

RangePrefixNumber of addressesTypical use
10.0.0.0 – 10.255.255.25510.0.0.0/8~16 millionLarge enterprises, carrier networks
172.16.0.0 – 172.31.255.255172.16.0.0/12~1 millionMedium networks, VPNs
192.168.0.0 – 192.168.255.255192.168.0.0/1665 536Home routers, small offices

Your home router most likely uses 192.168.1.0/24 or 192.168.0.0/24 internally. The range 172.16.0.0/12 is less well known but equally standard — you often see it in cloud environments (e.g. Docker uses 172.17.0.0/16 by default).

The trick lies in the port numbers. When your machine sends a packet out, the NAT router rewrites the source address to its public IP and changes the source port to a unique number that it stores in a NAT table. When the reply comes back, it looks up the port number in the table and sends the packet to the correct internal machine.

NAT is controversial

NAT violates the end-to-end principle: a machine behind NAT cannot readily accept incoming connections. It requires «port forwarding» to run a server at home, and peer-to-peer protocols must use «hole punching.» Routers «should» only process up to layer 3, but NAT manipulates port numbers (layer 4). Nevertheless: NAT is here to stay, widely used in home networks, enterprises and 4G/5G networks.

Why is NAT controversial among network architects, and which layers in the protocol stack does it violate?
NAT violates the end-to-end principle in two ways. First: a machine behind NAT cannot accept incoming connections without explicit «port forwarding» — servers, P2P and IoT become problematic. Second: a router normally operates at layer 3, but NAT rewrites port numbers (layer 4). This means a layer-3 device manipulates layer-4 information, which breaks the clean layering. In addition, the NAT router must maintain state (the NAT table) per flow, which contradicts the stateless IP model.
14 · IPv6

128-bit addresses and a simpler header

IPv6 was specified in 1998. The motivation: 32-bit addresses would run out. The solution: 128-bit addresses — enough to give every grain of sand on Earth its own address several trillion times over.

IPv6 has two advantages beyond the larger address space. First: a fixed 40-byte header without options or variable fields, which makes forwarding faster. Second: support for flow labels that let routers treat flows differently.

What was removed from IPv4?

  • No header checksum — saves time in routers (the transport layer has its own).
  • No fragmentation in routers — if the packet is too large, the router sends an ICMP «Packet Too Big» message back. The sender must fragment it itself.
  • No options — replaced by extension headers chained via «next header» fields.

Transition: tunneling and dual stack

IPv6 and IPv4 are not backward compatible. The transition requires dual stack (running both simultaneously) and tunneling (encapsulating IPv6 datagrams inside IPv4 payloads to cross IPv4 networks).

In 2026, we are around 45–47% IPv6 traffic globally — after more than 25 years of gradual migration. NAT kept IPv4 on life support and removed the pressure for a rapid transition.

Why does IPv6 have no header checksum, while IPv4 does?
In IPv4, the header checksum must be recomputed at every single router, because the TTL field is decremented at each hop. This costs time in a device that must process millions of packets per second. At the same time, both TCP and UDP have their own checksums that protect data and header end-to-end. The IPv6 designers concluded that a hop-by-hop checksum at the network layer was wasted processing — and removed it to make forwarding faster.
15 · The hourglass & end-to-end

The Internet’s architectural principles

IP is the Internet’s «narrow waist» — the only thing everyone must implement. Complexity lives at the edges. This is a deliberate design choice.

Syllabus note

Section 4.5 (Middleboxes) in the textbook is not part of the syllabus. The hourglass model and the end-to-end argument are nevertheless central architectural principles referenced throughout the course. This section provides useful background, but the exam focus is on sections 4.1–4.3.

The IP hourglass

The Internet has many protocols at the application, transport, link and physical layers — but only one network-layer protocol: IP. This «narrow waist» is what makes interoperability possible: any device that implements IP can communicate with any other.

In «middle age,» the Internet has developed «love handles»: middleboxes (firewalls, NAT, caches) that operate inside the network and break the clean hourglass model.

Architectural principles (RFC 1958)

★ RFC 1958

«The goal is connectivity, the tool is the Internet Protocol, and the intelligence is end to end rather than hidden in the network.»

Three cornerstones: simple connectivity, IP as the narrow waist, and intelligence at the edges.

The end-to-end argument

Saltzer, Reed and Clark (1981) put it this way: a function can only be implemented completely and correctly with knowledge from the application at the endpoints. Building it into the network itself is not possible. An incomplete version in the network may be useful as a performance optimization, but can never replace the endpoint implementation.

Concretely: reliable data transfer can either be implemented hop-by-hop in the network (expensive, complex) or end-to-end in the end systems (TCP). The Internet chose end-to-end — and it has scaled better than all alternatives.

What does the end-to-end argument mean in practice for network design?

Correct! The intelligence — reliability, encryption, ordered delivery — belongs in the end systems. The network is kept simple and focused on best-effort delivery.
16 · Summary

Simple by design

If there is one thing to take away from this chapter: the Internet’s network layer is simple by design. Every design decision — best-effort, dumb routers, hierarchical addressing, destination-based forwarding — is a choice against complexity.

The complexity is not gone — it has simply moved:

  • To the end systems: TCP ensures reliability, QUIC provides low latency.
  • To the control plane: BGP is one of the most complex systems humans have built.
  • To middleboxes: NAT, firewalls, load balancers, deep packet inspection.

The data plane has remained relatively simple — and that is why it has been able to fly. Next time, when we open the control plane section, we will see how forwarding tables are actually populated: routing algorithms, OSPF, BGP, and ICMP.
