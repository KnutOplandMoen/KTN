Network Security

How cryptography, digital signatures, TLS, IPsec, and firewalls work together to protect data traveling through a network full of potential attackers.

Overview

The big picture

Network security is about protecting data traveling through a network full of potential attackers — using four tools that each solve one specific problem.

Imagine you need to send a valuable diamond through a postal system full of thieves. You need: (1) a locked box that only the recipient can open (encryption), (2) a seal that shows if someone has opened the box en route (integrity / MAC), (3) a way to prove that it really is you who sent it (authentication / digital signatures), and (4) guards at the door who inspect every single package (firewalls). Each security tool solves one specific problem.

Real-world example

When you see the padlock in your browser on ntnu.no, it means TLS is active. The browser and server have completed a handshake where they agreed on encryption keys — and now everything you send is encrypted so that no one on the WiFi network can read it.

The toolbox — four layers of security

Symmetric encryption (AES) — fast, but requires both parties to share the same secret key.

Public key cryptography (RSA) — solves the key distribution problem, but is slow. Used to exchange session keys.

Message integrity and digital signatures (HMAC, RSA signature) — guarantees that the content has not been altered and that the sender is genuine.

Firewalls and IDS — filter traffic and detect suspicious activity on the network.

Test yourself

Check whether you have understood the most important concepts from this chapter.

Question 1
Alice wants to send a large, confidential file to Bob. Why doesn't she simply use Bob's public RSA key to encrypt the entire file directly?
Asymmetric encryption (such as RSA) is orders of magnitude slower than symmetric encryption (such as AES). Therefore, in practice hybrid encryption is used: generate a random symmetric session key KS, encrypt the file with KS (fast), and encrypt only KS with Bob's public RSA key. Bob decrypts KS with his private key, then uses it to decrypt the file. This is exactly what TLS and secure email do.
Question 2
What is the main difference between a MAC (Message Authentication Code) and a digital signature?
A MAC is based on a shared symmetric key — both Alice and Bob can create and verify the MAC, but neither can prove to a third party who created it. A digital signature uses the sender's private key, so only Alice can sign, while anyone with her public key can verify. This provides non-repudiation: Alice cannot deny having signed the message.
Question 3
During a TLS handshake, the server sends its certificate to the client. What does this certificate contain, and why is it necessary?
A TLS certificate binds a public key to an identity (e.g., ntnu.no), and this binding is signed by a trusted CA. Without the certificate, Trudy could impersonate the server (man-in-the-middle attack). The client verifies the CA's signature using the CA's public key (which is already built into the browser), and then trusts that the public key in the certificate really belongs to the server.
