The Network Layer:
The Control Plane

In chapter 4 we saw how a single router moves packets from input to output — the data plane. But who decides which output is correct? That is the control plane's job: to ensure that thousands of routers agree on the path, so that your packet actually arrives.

Overview

The GPS inside the network

The control plane is the invisible brain that computes the route — before the data plane lifts a single packet.

Think of it this way: you are sitting in a car and need to get from Trondheim to Bergen. The data plane is the car itself — the steering wheel, the pedals, the engine that physically moves you along the road. But the car alone is useless without a plan for which road to take. The control plane is the GPS. It gathers maps of all the roads, computes the best route, and tells the car at each intersection: "turn left here." Without the GPS, the car would just idle at every intersection, not knowing which direction to go.

In a real network, this is even more impressive. There is not just one GPS sitting on top and controlling everything. In the traditional Internet, every single router runs its own GPS computation. They talk to their neighboring routers, exchange information about which destinations they can reach and what it costs, and gradually — through routing algorithms — all agree on a consistent forwarding table. The alternative is SDN (Software Defined Networking), where one central controller acts as a super-GPS that computes the route for everyone and pushes the tables down to the routers.

When you send a message on Snapchat, it may need to pass through 15 routers. The control plane is what ensures that all of these routers agree on the path — before your message even leaves your phone. If just one router disagrees, the packet can end up in a loop, disappear, or take a detour via Tokyo.

But what happens when something goes wrong along the way — a router crashes, a link goes down, or a packet wanders in circles? Then the network needs a signaling language to report the problem. That is where ICMP (Internet Control Message Protocol) comes in: a small, humble protocol that lets routers and hosts shout "error!" or "are you there?" to each other. It is also the engine behind tools like ping and traceroute — the tools you use to troubleshoot networks in the real world.

The interplay between the two planes is the core of everything we cover in this chapter. The control plane can be organized in two ways: per-router control, where each router independently runs its own routing algorithm (how the Internet works today), or centralized control (SDN), where one controller computes everything and pushes the tables out. In addition, ICMP gives the network a signaling language for error messages — and gives us tools like traceroute to see exactly which path the packets take.

Test yourself

Check whether you have understood the most important concepts from this chapter.

Question 1
What is the main task of the control plane in the network layer?
The control plane is about routing — computing the best path through the network and filling in the forwarding table. The actual movement of packets (the fast per-packet operation) is the data plane's job.
Question 2
What is the difference between per-router control and SDN (Software Defined Networking)?
In per-router control, each router runs its own routing algorithm and talks to its neighbors to build its forwarding table. In SDN, a logically centralized controller does all the computation and distributes the tables to "dumb" routers that simply follow instructions.
Question 3
The command ping uses ICMP. Which two ICMP message types are involved?
ping sends an ICMP echo request (type 8) to the target. If the target is reachable, it responds with an ICMP echo reply (type 0). The round-trip time between these two messages is what ping shows you.
Question 4
How does traceroute manage to find the address of each router along the path?
Traceroute exploits the TTL field in the IP header. By sending packets with TTL = 1, 2, 3, ... it forces each router along the path to drop the packet and send an ICMP "TTL expired" message back — and that message reveals the router's IP address.
